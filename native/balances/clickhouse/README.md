# Native balances in ClickHouse

The Substreams CLI's native ClickHouse sink (`substreams sink clickhouse`)
loads the native map's `evm.balances.v1.Events` directly; there is no `db_out`.
A materialized view copies each insert into the legacy substreams-evm native
tables, whose aggregation view then runs unchanged. A TTL expires the sink's
own base rows.

```
Balance ──mv_sink_native_balances──▶ native_balances ──mv_historical_native_balances──▶ historical_native_balances_state ──▶ historical_native_balances (view)
_blocks_  (block table: number, hash, timestamp)
```

The sink runs the local manifest, `native/balances/substreams.yaml`, built from
source. That is the live-qualified BSC map: WASM `48d89d28…`, module
`5a2a2e0c…`, params `{"producer_versions":[5]}`. `make build` (the workspace
WASM build) reproduces that WASM.

| File | Creates | Source |
| --- | --- | --- |
| (sink setup) | `Balance`, `_blocks_` | generated by the sink from the package |
| `schema.1.table.native-balances.sql` | `native_balances` | verbatim upstream: lines 29–51 of `schema.1.table.balances.sql`, the native table |
| `schema.2.mv.historical-native-balances.sql` | `historical_native_balances_state`, `mv_historical_native_balances` | verbatim upstream |
| `schema.3.view.historical-native-balances.sql` | `historical_native_balances` | verbatim upstream |
| `schema.4.mv.sink-bridge.sql` | `mv_sink_native_balances` | new: `Balance` → `native_balances` |
| `schema.5.ttl.sql` | TTL on `Balance` | new: base-data retention |

Upstream is `pinax-network/substreams-evm@cb8607f` (`db-evm-balances-clickhouse`,
the evm-balances v0.3.4 build). `make schema` concatenates these files into
`schema.sql`, which `make setup` applies.

## Deploy

```sh
export SUBSTREAMS_SINK_DSN='clickhouse://<user>:<password>@<host>:9000/<database>'
export SUBSTREAMS_API_KEY=...
make -C native/balances/clickhouse setup
make -C native/balances/clickhouse dev START_BLOCK=<block> STOP_BLOCK=0
```

- **Build first.** `setup` and `dev` first build the release WASM that the
  manifest references.
- **`setup` order.** `setup` runs the sink's own setup, then applies
  `schema.sql`. The view must exist before the sink's first insert, because a
  materialized view sees only rows inserted after it exists. Re-running it is
  safe: the sink's tables are `CREATE … IF NOT EXISTS`, and its only
  compatibility check concerns the `_row_id_` column.
- **`dev` flags.** `dev` always passes `--final-blocks-only` and
  `--bytes-encoding 0xhex`. `STOP_BLOCK=0` streams without a stop block.
- **Start block.** `START_BLOCK` must be a producer-version-5 block. Any other
  `Block.ver`, a missing Extended block or ambiguous producer data stops the
  stream instead of writing guessed rows
  ([rules](../README.md#persistence-and-fail-closed-rules)).
- **DSN.** It is read from the environment and never echoed. The default is
  a local `default` database. An empty password (`user:@host`) makes
  `clickhouse client` print a password prompt and continue.
- **Local state.** The sink keeps its schema hash, cursor and spool under
  `localdata/`. Keep it with the database.

## Tables

- **`native_balances`.** `ReplacingMergeTree(block_num) ORDER BY address`:
  the latest observed balance per account. Read it with `FINAL`. Zero balances
  are kept. `block_hash` stays empty on this path; join `_blocks_` on
  `block_num = number` for the hash.
- **`historical_native_balances`.** OHLC bars per account at 1 minute to
  1 week. `transactions` counts blocks in which the account's native balance
  persistently changed.
- **`_blocks_`.** One row per block with output: `number`, unprefixed `hash`
  and `timestamp`.
- **Rows.** Rows come from every account whose balance changed in a block:
  transfers, internal calls, gas, fee rewards and system accounts. The RPC-era
  module emitted candidate accounts, including unchanged ones, so counts
  differ from RPC-era history. An account untouched since the cutover keeps its
  RPC-era value.
- **Undo.** The view copies every `Balance` insert. An undo, which
  `--final-blocks-only` prevents, would be copied too.
- **Replays.** A replayed flush, after a crash between insert and cursor
  write, inflates `transactions` for those windows. Latest values and OHLC
  values are unaffected.
- **No chain id.** Neither table stores one. Use one database per network.

## Base-data TTL

`Balance` holds one row per changed account per block, about 48.5 compressed
bytes per row. The sampled BSC windows averaged 134–164 rows per block, which
is about 1.25–1.5 GB a day. Each row is copied into `native_balances` and the
aggregation state when it is inserted, so the base table only serves audits
and rebuilds.

`schema.5.ttl.sql` sets `TTL _block_timestamp_ + INTERVAL 7 DAY` (about
9–11 GB of base data):
- **Expiry.** Background TTL merges remove expired rows, soon after insert for
  old blocks such as a backfill. The view never sees these deletions.
- **No TTL on `_blocks_`.** It is small, about 14 MB a day.
- **Changing retention.** Run `ALTER TABLE Balance MODIFY TTL …` with a new
  interval at any time.

## Backfill from the RPC-era database

Start the sink at block `S` in a fresh database, where the RPC-era sink's last
block is `S-1`. Then copy history with
[`examples/backfill-from-rpc-database.sql`](examples/backfill-from-rpc-database.sql).

It uses partition copies, because `INSERT … SELECT` into `native_balances`
re-fires `mv_historical_native_balances` and double-counts `transactions`.
`AggregatingMergeTree` merges the windows that span `S`. RPC-era block records
can optionally be inserted into `_blocks_`.

## Checks (2026-10-03)

- **Real setup.** `make setup` ran twice against a fresh database on a local
  server, with Substreams CLI `be35ad3` and ClickHouse 25.8.1.3064. It created
  all seven objects with the TTL in place.
- **Live-shaped data.** The native map's output for the saved-control blocks
  122,288,006–122,289,029 (all 76,139 rows equal to `eth_getBalance`) and the
  live blocks 123,561,000–123,562,023 was loaded the way the sink writes it,
  through the sink's DDL and `schema.sql`, in clickhouse-local:
  - `native_balances` (17,670 and 35,092 accounts) equal independently
    computed values;
  - every `historical_native_balances` bar (164,379 and 350,250) equals them
    too;
  - `_blocks_` matches the expected block records;
  - the legacy tables were unchanged after the TTL removed the base rows.
- **Backfill.** The backfill example, run against an RPC-era database created
  from upstream's full schema, equals a single-pipeline baseline: latest
  balances, all 973 bars including 35 spanning the cutover, and block records.

None of this streamed. A bounded live run into a fresh database is the
remaining step.
