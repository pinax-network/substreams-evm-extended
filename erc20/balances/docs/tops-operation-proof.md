# TOPS: bounded host operation proof (Phase A)

This **NOT-QUALIFIED** proof concerns captured direct TOPS token
`0xcdf52c0b13c24f32f1d8d4ec6356203a1ef0826a` on BSC. It adds host diagnostics
and tests only. All six issue #61 profiles remain excluded; the canonical layouts,
production parser, persisted-effect rules, protobuf, dependencies and WASM ingestion
path are unchanged. There is no array validator or replacement candidate.

The two proof domains remain separate:

- The complete original runtime executes `createLPInfo`, raw `balanceOf`,
  `lpInfos`, `lpAmount` and the two LP aggregate getters against synthetic state.
- A separately compiled harness executes the byte-identical private cleanup body
  and aggregate getter bodies. Its storage roots and three-word record stride
  match the original, but **its physical write order does not qualify the deployed
  transfer path**. It proves the extracted source semantics only.

Original transfer and constructor execution stop at unsupported GAS immediately
before external calls. These are explicit `HarnessFailure` controls with attempted
effects retained and committed state/logs rolled back. They are not successful
transfers/constructors or Solidity reverts. No mock callees, external-call emulator,
ORIGIN, gas accounting or fork-cost model was added.

## Semantics and controls

`balanceOf` reads root 5 only. Array records at root 31 have three uint256 words:
amount, creation time and expiry. Root32 holds available LP amount. `createLPInfo`
is miner-only, rejects zero user/amount, and checks timestamp +100 days before
appending. The measured struct-array push permits old length below 2^64, including
2^64−1→2^64, and returns `Panic(0x41)` at 2^64/MAX before any write. The autogenerated
out-of-range `lpInfos` getter returns empty REVERT, not `Panic(0x32)`.

Cleanup scans only the expired prefix, treating expiry equality as expired and
stopping at the first future expiry even if later records are expired. Its sum
wraps modulo 2^256. **If that sum wraps to zero, no record is removed or credited.**
Otherwise it compacts the suffix forward, clears tail records, decrements length
and credits root 32 with wrapping arithmetic. The aggregate getters use checked
arithmetic and can revert for states whose cleanup succeeds. Root32 also has
independent constructor/liquidity writers, so a future validator cannot assume
an unconditional global array/credit coupling invariant.

The matrix covers empty through six-element arrays and all prefix cutoffs,
overlapping compaction, equal/zero-valued fields, out-of-order expiries, wrapping
sums/credits, checked getter overflow, timestamp 0/MAX/+100-day boundaries, miner
refusals, ABI errors and extreme lengths. Every case compares exact exit data,
all committed storage including untouched padding/sentinels, full log sequences,
ordered SSTORE old/new words and required reads. Raw attempts are saved before
source annotation or expectation checking; partial reports survive failure.
The constructor boundary also verifies its 17 independently packed attempted
stores and ownership log before rollback. Its optimized ownership log precedes
those stores; source declaration order is not substituted for measured order.

The small shared VM adds only optional full-word TIMESTAMP. Every legacy entrypoint
leaves it absent and fails closed if encountered. Direct tests cover absent/zero,
large words/MAX, repeated reads, rollback and unsupported neighboring operations.
The [pinned execution specification](https://github.com/ethereum/execution-specs/blob/3e170675290673a68eeb4652501fb2ae74fea0cb/src/ethereum/forks/cancun/vm/instructions/block.py#L101)
and CC0 notice are preserved; only opcode stack semantics are implemented.

A separate regression compares the original block 123561227 / transaction 63 five-pop,
21-write metadata subsequence with the source harness under an explicitly
synthetic all-expired clock. It preserves the historical refusal and does not
claim full captured transaction execution or a saved-block replay.
